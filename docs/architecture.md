
# Архитектура DevTest Hub

## 1. Назначение системы

DevTest Hub — веб-платформа для автоматического создания
и управления тестовыми средами разработчиков.

## 2. Пользователи системы

Основные пользователи — разработчики программного
обеспечения и администраторы инфраструктуры.

## 3. Основные возможности

- Создание тестовой среды из шаблона
- Запуск и остановка тестовой среды
- Удаление тестовой среды
- Просмотр состояния контейнеров
- Просмотр журналов работы
- Проверка результатов автоматических тестов

## 4. Основные компоненты

### Frontend
Пользовательский интерфейс веб-приложения.

### Backend
REST API на Python и FastAPI.

### PostgreSQL
Хранение информации о пользователях, средах и операциях.

### Redis
Передача фоновых задач.

### Worker
Выполнение задач развёртывания.

### Docker
Запуск изолированных контейнеров.

### Docker Swarm
Кластерное развёртывание сервисов.

## 5. Взаимодействие компонентов

Создание тестовой среды выполняется асинхронно.

1. Пользователь выбирает шаблон тестовой среды через Frontend.
2. Frontend отправляет HTTP-запрос в Backend.
3. Backend проверяет параметры и сохраняет информацию о задаче в PostgreSQL.
4. Backend помещает задачу в очередь Redis.
5. Worker получает задачу из очереди.
6. Worker инициирует развёртывание разрешённых Docker-сервисов.
7. Состояние выполнения задачи обновляется в PostgreSQL.
8. Frontend получает текущий статус через REST API.
9. После успешного развёртывания пользователь получает адрес тестовой среды.

Такое разделение позволяет выполнять длительные операции
без блокирования обработки HTTP-запросов.

Доступ к управлению Docker предоставляется только доверенному
компоненту развёртывания. Пользователь не получает прямой
доступ к Docker Engine.

## 6. Безопасность

Развёртывание выполняется из разрешённых шаблонов.
Прямой доступ пользователей к Docker Engine запрещён.

## 7. CI/CD

Автоматизированные тесты, сборка и развёртывание
реализуются с помощью GitHub Actions.
